# MatSci-RAG V1.0 图形封装运行包

软件名称：**基于证据图谱的材料文献智能问答系统 V1.0**。

本包提供一个统一的本地图形入口 `app.py`，把已提供的九个后台源码模块连接到可操作的界面。欢迎页用于展示软件名称、版本和功能入口；系统首页展示当前任务与处理进度；各功能页展示对应的真实处理结果。

这是一套 Python 图形封装代码，通过本机浏览器运行。它不是独立 EXE 安装程序。“外包装界面”在本包中指软件欢迎页。

## 1. 先打开界面

建议使用 Python 3.11 或 3.12，并单独创建环境。界面已在 Python 3.12、Streamlit 1.65.0 下验证。

在解压后的目录运行：

```bash
python -m pip install -r requirements-ui.txt
python -m streamlit run app.py
```

Windows 安装界面依赖后可以直接双击 `start_windows.bat`；Linux/macOS 可运行 `bash start.sh`。浏览器地址为 `http://127.0.0.1:8501`。运行期间保留终端窗口，按 Ctrl+C 停止服务。

仅安装界面依赖即可打开欢迎页、首页、所有功能页，也可处理已有 Markdown 的文本规范化和结构化解析。尚未运行的功能显示“待执行”，没有填充演示问答或虚构成功数据。

## 2. 配置完整功能

如果已有能够运行原始 MatSci-RAG 源码的环境，优先在该环境安装 `requirements-ui.txt`。这样可继续使用已经验证的模型和依赖。

如需新建完整环境：

```bash
python -m pip install -r requirements-full.txt
```

`requirements-full.txt` 按源码导入列出后台依赖，不是已验证的完整锁定环境。科学分句模型、PyTorch/CUDA 和相关依赖的版本需按实际运行环境适配。

| 项目 | 配置方式 | 使用阶段 |
| --- | --- | --- |
| Doc2X 服务密钥 | 将 `.env.example` 复制为 `.env`，填写 `DOC2X_API_KEY` | PDF 转 Markdown |
| 智谱服务密钥 | 同一 `.env` 中填写 `ZHIPUAI_API_KEY` | 元数据生成、问答与抽取 |
| 科学分句模型 | 安装与当前 spaCy/scispaCy 版本兼容的 `en_core_sci_sm`，或填写已有模型名称/目录 | 图谱构建 |
| 嵌入模型 | 默认 `BAAI/bge-large-en-v1.5`；可在配置页改为已下载的本地目录 | 分块长度检查、元数据、索引、检索 |
| 重排序模型 | 默认 `BAAI/bge-reranker-large`；可使用本地目录 | 问答与抽取 |
| 计算设备 | 默认 `cpu`；具备匹配的 CUDA 环境后可选择 `cuda` | 向量化与推理 |
| 图片资源目录 | 在“系统配置”中填写已导出的图片资源根目录 | 多模态输入与关联图片展示 |

云服务调用和模型下载需要网络与相应服务权限。系统不自动安装模型，也不包含模型权重或服务密钥。配置页不显示密钥；处理日志展示前会遮蔽配置文件中的密钥值。

科学分句模型的安装说明以 [scispaCy 官方项目](https://github.com/allenai/scispacy) 为准。界面 API 以 [Streamlit 官方文档](https://docs.streamlit.io/) 为准。

## 3. 正常操作顺序

1. 打开软件欢迎界面，点击“进入系统工作台”。
2. 设置左侧任务编号，例如 `paper001`。一个任务对应一篇文献；不同文献建议使用不同任务编号。
3. 在“文献预处理”上传 PDF 或 Markdown，也可填写本机文件路径，然后点击“导入当前文献”。
4. PDF 执行“转换为Markdown”后执行“规范化文本”；已有 Markdown 可直接规范化。也可点击“连续预处理”。
5. 在“结构化解析”执行“解析文献结构”，查看章节、图像、表格和公式。
6. 在“证据图谱”执行“构建证据图谱”，查看局部关联图、节点详情和关系清单。
7. 在“元数据处理”执行“提取并合并元数据”，核对文献书目信息和材料主题。发生模型回退时界面会提示核对。
8. 在“索引创建”执行“创建向量索引”，核对章节桶、文档数量、向量维数和长度检查结果。
9. 在“智能问答”选择“文献问答”或“结构化信息抽取”，输入实际问题并提交。
10. 在“结果与追溯”查看历史结果、检索证据、关联图表、证据 UID 与来源记录，并下载结果。

首页的“一键构建知识库”会按上述建库顺序执行，不包含问答。配置中可以选择一键建库是否包含元数据处理。后台处理在独立进程中运行，页面会更新进度；执行期间同一任务不能重复提交或替换输入。

重新执行上游步骤会将下游步骤标记为“需重新执行”。问答前会核对索引模型与当前嵌入模型，并检查图谱是否在建库后被修改。更换输入时会清除当前步骤状态，后续转换与元数据处理会重新读取输入；历史结果文件仍会保留，因此更换文献时建议另建任务。

## 4. 连接已有知识库

在“系统配置”填写已有知识库的 `output` 目录，目录应包含原始源码生成的 `paper_graph.json`、`retrieval_docs.jsonl` 和 `faiss_section_indexes/faiss_index_manifest.json` 及实际索引文件。左侧任务编号必须与图谱的 `doc_id` 相同。保存配置后点击“连接已有知识库”。

如果只导入图谱和检索文档，可以查看图谱，补建索引后再问答。配置中的嵌入模型必须与已有索引清单一致。建议连接前复制一份已有输出目录作为工作副本，因为在界面中重建图谱或索引会写入所选目录。只使用可信的本地 FAISS 输出。

已有知识库并不包含本界面的源文件导入记录和中间结构化 JSON，因此预处理、结构化解析及元数据重新生成需要相应上游文件。连接后可直接使用图谱、索引与问答页面。

## 6. 文件与接口对应

| 图形功能 | 实际源码入口 |
| --- | --- |
| PDF 转换 | `build_demo.run_pdf_stage` → `pdf_to_md.pdf_to_md` |
| 文本规范化 | `build_demo.run_clean_stage` → `clean_md.clean_markdown_file` |
| 结构化解析 | `build_demo.run_md_json_stage` → `md_json.convert_markdown_file` |
| 证据图谱构建 | `build_demo.run_graph_stage` → `json_split` |
| 元数据与图谱合并 | `build_demo.run_metadata_stage`、`run_merge_stage` → `metadata_processor`、`merge_metadata_to_graph` |
| 索引创建 | `build_demo.run_embedding_stage` → `embedding_json.build_indexes` |
| 文献问答与抽取 | `main_pipeline.build_pipeline_from_output_dir` → `pipeline.run` |
| 结果追溯 | 读取同一次运行保存的 `retrieval_debug`、`render_payload`、`evidence_trace`、`source_map` |

用户只启动 `app.py`，不需要分别启动后台模块。后台源码放在 `backend/`，保持原始内容不变。后续如补充或更新源代码，替换对应模块即可；若函数签名或返回结构变化，需要同步调整 `app.py` 中的 `execute_stage()` 和结果展示部分。

默认工作文件保存在 `workspaces/<任务编号>/`：`source/` 保存输入，`intermediate/` 保存清洗文本与结构化 JSON，`doc2x_output/` 保存转换产物及图片，`output/` 保存图谱、元数据和索引，`results/` 保存问答结果，`jobs/` 保存任务记录与日志。配置项保存在 `gui_settings.json`。

下载的追溯 ZIP 包包含本次结果、图谱、检索文档和索引清单，不包含图片资源、模型权重和实际 FAISS 索引。完整迁移时应另外复制任务目录和模型资源。

## 7. 验证情况与边界

已验证：欢迎页/首页与各功能页的初始显示、浏览器中的欢迎页进入工作台与功能导航、截图模式、本地 Markdown 导入、后台进程调度、原始文本清洗与结构化解析、真实章节和表格统计展示、任务路径检查、输入变化后状态失效、索引模型不一致的拒绝处理。

本环境未配置 Doc2X/智谱服务密钥、完整科学分句与嵌入/重排序模型，尚未完成真实 PDF→图谱→索引→模型问答的全流程验证。完整功能依赖原始源码、模型、密钥和文献格式，不能仅凭界面打开推断后台全流程已通过。

本封装保留现有单篇文献流程，不增加跨文献联合检索，也不改变原始 RAG 的算法、元数据索引利用方式或证据声明生成逻辑。检索证据和来源追溯来自后台原始输出。

常见问题：依赖缺失时按提示安装；章节为空时核对 Markdown 标题格式；缺少图片时核对资源目录；模型与索引不一致时恢复原建库模型或重新建库；元数据提示回退时核对内容；服务失败时检查配置和实际处理日志。
